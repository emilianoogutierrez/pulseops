# Contributing

Keep changes narrow, tested and explainable.

1. Create a branch for one coherent change.
2. Preserve workspace scoping in all business-data queries.
3. Add or update tests when changing domain behavior.
4. Run `npm run verify` before opening a pull request.
5. Describe architectural tradeoffs in an ADR when a change introduces a new infrastructure boundary.

Commit messages use conventional prefixes such as `feat:`, `fix:`, `test:`, `docs:`, `refactor:` and `ci:`.
